## Essential batch 1: identity and images

1. Artist name and a short bio, ideally 2–4 sentences.
2. Visual mood, additional references and any existing logo, colors or typography.
3. Portrait/photos and permission to publish them.
4. Release artwork and its credits, if relevant.

## Essential batch 2: music and destinations

1. Featured release: title, format, year/date, description and artwork.
2. Discography: the same information for other releases.
3. Spotify, Apple Music, Bandcamp, SoundCloud and other streaming links; which embeds to use.
4. Social profile URLs and the order of the link hub.
5. Public contact email and whether it is for booking, general contact or both.

## Last.fm choices

1. Use an existing Last.fm account? Supply its public username, or choose manually curated listening picks.
2. Which features: recent tracks/now playing, top artists, dated listening history, recommendations or a combination?
3. For top artists, which time period: week, month, year or all time?
4. For recommendations, prefer manually chosen picks or similar artists derived from listening? The current scaffold only connects recent tracks and top artists.
5. Is the account's listening activity appropriate to publish here? API key setup happens locally after choosing live mode.

Recent/top reads need a username and an API key. They do not require a password or scrobbling session. Extended history would use pagination/date filtering on recent tracks; similar-artist discovery would use artist.getSimilar. Neither is part of the current structure. There are no visitor accounts, social-network features or scrobbling infrastructure.

## Launch batch

1. Monthly hosting budget and annual domain budget.
2. Technical comfort: prefer clicking through a setup, comfortable with a terminal, or already manage Linux/Docker?
3. Preferred domain and alternate names if unavailable.
4. Existing hosting/domain accounts or an existing server to reuse.

## Optional, choose only what you need

1. Tour dates and ticket destinations.
2. Merchandise/store destination.
3. Videos and embed links.
4. Mailing list provider and signup destination.

None of these optional services requires becoming part of the site's own backend unless that is explicitly chosen. All accounts and infrastructure should remain in the artist's ownership.
